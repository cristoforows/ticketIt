# Execution interface contract

Status: behavior agreed during M1, reconciled with what M4 and M5 shipped ([M4 evidence](../evidence/m4/README.md), [M5 evidence](../evidence/m5/README.md)). HTTP polling is the transport ([ADR 0003](../adr/0003-postgresql-work-claims-before-queue.md)) and [`contracts/openapi.yaml`](../../contracts/openapi.yaml) is the authority for paths, payloads and error codes; this document states behavior and ownership. Parts marked **M7 (#8)** or **M8 (#9)** are not implemented. Only Michelin's controlled engine runs. No provider is chosen here (see [open-decisions.md](../open-decisions.md)).

This document covers two boundaries:

1. **Galley ↔ Michelin**, the execution interface. Michelin reports execution facts and pulls commands; Galley owns every authoritative decision.
2. **Swiftlet → Galley**, the owner-command boundary. Swiftlet submits owner commands and renders Galley-provided state.

Sources: [v1 spec #1](https://github.com/cristoforows/ticketIt/issues/1) sections "Applications and ownership," "Ticket model and contracts," and "Execution and state transitions"; [v1-scope.md](../v1-scope.md); [implementation-plan.md](../implementation-plan.md) "Proposed boundaries and records"; [agent-execution.md](../agent-execution.md); [deployment.md](../deployment.md); [integration-feasibility.md](../integration-feasibility.md).

## Ownership statement

- **Galley alone mutates authoritative records**: Ticket Status, Round outcome, Permission grants, and usage observations. No other application writes these directly.
- **Michelin never sets Ticket status directly.** It reports execution facts as events. Galley's own state machine interprets those facts and decides the resulting Status and Round outcome.
- **Swiftlet never talks to Michelin.** It submits owner commands to Galley and renders the state Galley returns. There is no direct browser-to-runner channel.
- Engine frameworks (LangGraph checkpoints, OpenCode sessions) hold execution-internal state. That state is not a substitute for Galley's Round record, and it never drives Ticket status on its own.

## Identity model

- **Round ID**: a UUID issued by Galley. A Round is ticketIt's unit of Agent work on a Ticket, with its own activity, result, and usage, independent of any engine's internal identifiers. A Ticket's Rounds are numbered by `sequence`.
- **Engine execution reference**: an OpenCode session ID or a LangGraph thread ID. It is a separate record attached to a Round, not the Round itself.
- **At most one current engine execution reference per Round**, attached by `execution_started`. A Round is never reattached to another execution: a stranded Round ends by Owner attestation, and further work is a new Round after Ready (D5).
- **Engine references never drive Ticket status.** Only Galley-interpreted events (below) change Status or Round outcome. The presence, absence, or internal state of an engine session/thread proves nothing about Ticket status by itself.
- A Round is created by Galley at the moment its work claim is admitted (see "Work claim"), carrying the fencing token from that claim (`claimEpoch`, increasing per Ticket, so Round 2 of a Ticket never shares Round 1's epoch). Creating the Round does not by itself move the Ticket to In Progress; that happens only when Michelin reports `execution_started`, so a claimed-but-not-yet-started Round is never falsely shown as running.

## Runner registration and health

- **Pair**: the Owner issues one runner credential per Owner (`POST /api/runner-credential`, Owner session). The token is returned once; Galley stores its SHA-256 hash. Pairing again revokes the previous credential. Runner routes under `/api/runner/` accept only this bearer token, and Owner routes refuse it.
- **Register**: Michelin calls `POST /api/runner/register` on start, sending its version and hostname. Registration also counts as a heartbeat. A credential that has not registered since it was issued gets `409 runner_not_registered` from the heartbeat.
- **Heartbeat**: `POST /api/runner/heartbeat` records last-seen. Health is derived on read: `connected` while the last heartbeat is under 30 s old, `disconnected` after that or before the first, `not_paired` without a credential. An event, claim, Reconcile or authority check is not a heartbeat, and an event from a runner that is not connected is still accepted. Registration, and a heartbeat whose previous last-seen is absent or at least 30 s old, flag the Owner's open Round as needing a Reconcile (`reconcileRequired`).
- **Disconnect rule**: lost contact never proves execution stopped. When heartbeats stop arriving within the window, Galley marks the connection lost, pauses admission of new work (a claim gets `204`), keeps the affected Ticket locked, and shows a Runner disconnected indicator. This is not a Status transition by itself: a Ticket already In Progress stays In Progress, locked, with the indicator overlaid, until the runner reconciles (below) or the Owner attests cessation ("Stranded Round").
- While the runner is disconnected or the Round awaits a Reconcile, an authority check is refused (`409 runner_disconnected`, `409 reconcile_required`), so no new action is admitted.

## Work claim

- **Eligibility**: the Ticket is unarchived, Ready, and Agent-assigned; it has a goal and Success Criteria; actual execution prerequisites are met. M4 requires a non-blank repository when the assigned Agent's kind is `coding`, whatever the Template; mapping it to a checkout the runner can use is **M8 (#9)**. Galley publishes the result as `Ticket.requestingAgentWork` and refuses Ready, however reached, while an input is missing (`agent_readiness_incomplete`). In Progress, In Review and Blocked on an Agent-assigned Ticket are set by execution only (`agent_owned_transition`). [D3](../decisions/d3-agent-template-compatibility.md) permits any Agent on either Template. Validate required inputs and action authority, never a template/capability whitelist. A Round may contribute without completing the whole Ticket, whose completion condition remains unchanged.
- **Atomic claim**: Michelin calls `POST /api/runner/claims` with an `idempotencyKey`, one per claim attempt and reused until a definite answer. Galley admits at most one claim per request in a single transaction, re-checking the Ticket under its row lock, issuing a fencing token (claim epoch) and creating the Round record held by the calling runner (`201`, with the Round, `claimEpoch`, the Ticket's inputs and any unconsumed Round Feedback). A key already used returns `200` with the body first returned, `409 idempotency_key_conflict` when another runner used it, or `409 claim_not_replayable` once its Round has left `claimed`. `204` means no Round exists for the key: nothing is requesting work, a Round is already open, or the runner is not connected. This prevents two runners, or two claim attempts, from both starting the same Ticket. Michelin does not persist the key, so a restart between commit and answer leaves a stranded Round.
- **Sequential scheduling**: one open Round per Owner, enforced by a partial unique index, across the native and OpenCode engines. A Round that is Waiting for Input keeps its slot; it does not free capacity for another Ticket while paused. Delivery, Stopped, Failed and Interrupted free the slot.
- **Queue order**: the claim takes the first eligible Ready Ticket in the Owner's persisted priority order (`priority_rank`, then id), set by `POST /api/tickets/{id}/position`. Capture goes to the top; entering Ready, including by rework, goes to the bottom of the order. `created_at` is not priority ([#108](https://github.com/cristoforows/ticketIt/issues/108)).
- **Archive-versus-claim race**: archiving and claiming are mutually exclusive under the same transactional guard. If an archive request commits first, the Ticket is no longer eligible and the pending claim is rejected. If a claim already produced an open Round, archiving is rejected (`400 round_open`) until that Round ends, consistent with the requirement that any open Round end before archive. Every other Owner mutation of a Ticket with an open Round (claimed, running or waiting for input, Stopping included) is rejected the same way.
- **Stranded Round** (D5): a Round whose runner never returns, or whose restarted runner cannot confirm its execution, stays open and locked; no timeout ends it. The Owner ends it with `POST /api/tickets/{id}/rounds/{roundId}/attest-cessation` (`basis`: `runner_process_ended`, `runner_host_off` or `other` with a `note`). It is offered (`allowedActions.attestCessation`) unless the claiming runner is the Owner's current runner, connected, and its last Reconcile did not report `unknown`; otherwise `400 attestation_not_available`. The Round ends `interrupted`, even with a Stop pending, which is never delivered, with the explanation `Ended by Owner attestation: <basis>.`; the Ticket moves to Blocked and the slot is freed. Galley records what it observed (`RoundAttestation`: holder health and last-seen, claim epoch, last Reconcile belief). The attestation is the Owner's assertion, not proof: a later report from the old process is `409 round_not_open`, and what it already did outside ticketIt stands.

## Events reported by Michelin

Every event is a fact report, not a request for permission. Each carries an idempotency key and the fencing token/claim epoch for the Round it reports on, and only the runner that claimed the Round may report it (`409 runner_not_holder`). Galley treats a replayed event (same idempotency key) as a no-op producing no new effect, and rejects an event carrying a fencing token that is not the Round's current claim epoch, without changing any state.

**Wire.** Every event uses one endpoint, `POST /api/runner/rounds/{roundId}/events`, with body `{type, idempotencyKey, claimEpoch, occurredAt, data}`; the Round is the path, not a body field. `type` is one of `execution_started`, `progress`, `usage_observed`, `delivered`, `stop_confirmed`, `failed`, `interrupted`, `question_raised`, `resumed`, `permission_requested`. Galley checks in order: authentication, Round lookup (unknown, malformed or foreign is the shared `404`), body shape (`400`), holder (`409 runner_not_holder`), replay by `(roundId, idempotencyKey)`, epoch, Round open, and event suited to the Round's state. A replay with the same payload returns the stored result with `200`; the same key with another payload is `409 idempotency_key_conflict`; then `409 stale_claim_epoch`, `409 round_not_open` and `409 event_out_of_order`, followed by the type's own checks below. A rejection changes nothing. `occurredAt` is the runner's clock; Galley times the Round by its own. Bodies over 8 MiB are `413`. After an accepted event Galley checks the Round's technical limits ("Revocation and technical limits").

Replay no-op; stale token rejected. |

No Status change. Replay no-op; stale token rejected. |

Reviewed-PR merge is not one of these events. A Ticket in In Review has no open Round, so there is no claim epoch to fence against. Michelin's GitHub connection can check merge status, and the owner can confirm merge in Swiftlet; either path reports that fact to Galley outside the Round-fencing model, using a Ticket-scoped idempotency key instead. The concrete transport for that check, and exceptional-PR handling, are routed to **D2** and **D4** (owned by M8).

## Commands pulled by Michelin

Michelin polls `GET /api/runner/rounds/{roundId}/commands`; commands are not pushed. Each `RunnerCommand` has an `id` (its idempotency key), a `type` (`stop`, `answer`, `approval`, `authority_changed`), the `claimEpoch` it targets and `issuedAt`. A command stays listed until Michelin acknowledges it with `POST /api/runner/rounds/{roundId}/commands/{commandId}/ack` (`outcome`: `applied` or `ignored`); a repeat with the same outcome returns the stored acknowledgement and another is `409 command_already_acknowledged`. Galley lists `stop` first, then `authority_changed`, then the rest by `issuedAt` (`listRoundCommands`' description omits `authority_changed`'s place: [#199](https://github.com/cristoforows/ticketIt/issues/199)). Nothing is listed once the Round has ended or for a runner other than its holder, and an acknowledgement from another runner is `409 runner_not_holder`. An acknowledgement never changes the Round or the Ticket.

| Command | Direction | Purpose | Required fields (in words) | Idempotency key | Fencing / claim epoch | Outcome |
| --- | --- | --- | --- | --- | --- | --- |
| Stop (`stop`) | Galley → Michelin | Instruct the runner to stop the open Round's execution. | Round ID, the claim epoch the command targets, `issuedAt`. | One per Round: the Owner's Stop, a revocation covering the Round and a limit breach share it. | A runner holding another epoch acknowledges it `ignored`. | Ticket shows Stopping, locked, until `stop_confirmed`. Michelin halts before its next step, confirms, then acknowledges `applied`. |
| Answer (`answer`) | Galley → Michelin | Deliver the Owner's answer to the pending question. | `answer.questionId`, `answer.text`. | One per question; the first answer stands (`question_already_answered`). | As Stop. | Michelin continues the same Round and reports `resumed`. |
| Approval (`approval`) | Galley → Michelin | Deliver the Owner's approval of the pending Permission request. | `approval.requestId`, `approval.grantId`. | One per request; a second decision is `permission_already_decided`. | As Stop. | Michelin reports `resumed` and still checks authority before acting. The approval also queues `authority_changed` for each open Round the grant covers. A decline sends no command; the Round waits until Stop. |
| Authority changed (`authority_changed`) | Galley → Michelin | Notify the runner that a grant covering the Round was approved or revoked. | No data. | Informational; repeated delivery is a safe no-op. | Not fenced by epoch. | Michelin checks live authority before its next action, as always. Expiry sends none. Already-dispatched actions may still finish; they are not undone. |

## Live authority checks

- Before each action, Michelin calls `POST /api/runner/rounds/{roundId}/authority-checks` with `{account, action, resource, epoch}`. Galley answers `allow` (naming `grantId`) or `deny` from the grants it holds at that moment and records the check. There is no grant snapshot anywhere: not in the claim, the Reconcile answer or a command.
- `allow` needs an active grant for the Round's Agent, of `ticket` form for this Ticket or `time` form unexpired by Galley's clock, for the same scope or full access to the same Connected Account. A `deny` names the newest expired time grant for that scope as `expiredGrantId`, which a `permission_requested` renews as `renewsGrantId`.
- A scope the account does not declare is `400 capability_not_supported`, whatever the grants. `runner_not_holder`, `stale_claim_epoch`, `round_not_open`, `runner_disconnected`, `reconcile_required` and `round_not_running` refuse the check, record nothing and are not denials.
- Ticket grants end at Done (`ended_at_done`) and stay ended if the Ticket is reopened; a grant approved afterwards works. Time grants are unaffected by Done.

## Question and permission waits

A necessary question or Permission need pauses the Round without ending it:

- The Round becomes Waiting for Input; the Ticket becomes Blocked and stays locked with its active-card treatment and View/Stop controls.
- The Round keeps its sequential execution slot; no other Ticket is admitted while it waits.
- The Owner answers (`POST /api/tickets/{id}/rounds/{roundId}/questions/{questionId}/answer`) or decides (`.../permission-requests/{requestId}/approve` with `form` `ticket` or `time`, an `expiresAt` for `time`, and `scope` `requested` or `full`; or `.../decline`). Galley records the decision and queues an `answer` or `approval` command.
- A second answer or decision is refused (`question_already_answered`, `permission_already_decided`) and produces no second effect; both are refused once Stop is requested (`stop_already_requested`).
- Answering resumes the same Round on its `resumed` event; it does not start a new Round. A Michelin restarted while a Round waits does not resume it; that Round is stranded.

## Stop with evidence-bearing confirmation

- The Owner's Stop (`POST /api/tickets/{id}/stop`) records one `stop` command for the open Round and sets `openRound.stopRequestedAt`; the Ticket stays locked with the `stopping` waiting reason. Without an open Round it is `stop_not_available`; a repeat returns the Ticket unchanged.
- Michelin pulls `stop`, halts the engine at its next step, and reports `stop_confirmed` only once it has evidence that execution ceased.
- Only `stop_confirmed` ends a Round as Stopped, and a later event for it is `409 round_not_open`. No other signal (disconnect, timeout, or an unacknowledged Stop command) is treated as confirmation; a Round whose runner never confirms stays Stopping until it reconciles or the Owner attests.
- The Stopped Badge is removed by the Owner and never changes the Round's outcome. Only an explicit Ready starts a new Round, with a new identity and epoch.

## Revocation and technical limits (D8)

- `POST /api/grants/{grantId}/revoke` ends a grant at once: no later check is allowed by it. Each open Round it covers gets the shared Stop and an `authority_changed` command. An action allowed before the revocation may complete and stays recorded. An expired grant is refused (`grant_expired`) and one ended at Done is `grant_ended`.
- Per Round, Galley measures active time while `running` (`GALLEY_ROUND_MAX_ACTIVE_DURATION`, default 4h) and denied authority checks since the last allowed one (`GALLEY_ROUND_MAX_CONSECUTIVE_DENIALS`, default 10), from its own records, never from a usage figure. Limits are evaluated after each heartbeat, accepted event and recorded check, so a silent runner is not measured. A breach records `limitBreach` and requests the shared Stop once; `stop_confirmed` then ends the Round `failed`. The check that reaches the denial limit still answers `deny`. Defaults for real engines are **M7 (#8)** and **M8 (#9)**.

## Reconciliation on reconnect

- Registration, or a heartbeat after a gap past the health window, flags the Owner's open Round (`reconcileRequired` on the register and heartbeat answers). While flagged, the Round's waiting reason is `reconciling`, or `execution_unknown` after a Reconcile that could not confirm execution, unless a reason earlier in `RoundWaitingReason`'s precedence applies; its authority checks are `409 reconcile_required`.
- Michelin calls `POST /api/runner/reconcile` with `held`: the Round it holds, its `claimEpoch` and its belief (`running`, `stopped` or `unknown`), or nothing. Galley answers `round` (the Round's `state`, `ticketStatus`, current `claimEpoch`, one `disposition` and its unacknowledged `commands`, Stop first), or `null` when nothing was held and the Owner has no open Round. The answer carries no grant snapshot: authority is checked per action.
- Dispositions: `continue` when execution is intact at the current epoch with no Stop requested, resuming the same Round; `stop` when a Stop is requested and not confirmed, halting before the next step and then confirming; `report_cessation` when the runner believes execution stopped, naming the `cessationEvent` (`stop_confirmed` with a Stop requested, else `interrupted`) that alone can end the Round; `hold` when execution cannot be confirmed, executing nothing for the Round, which stays open and locked. `unknown` is answered as if nothing were held. A runner holding nothing while another runner's Round is open gets `hold` with no commands, and nothing is recorded.
- A non-holder is `409 runner_not_holder`, a wrong epoch `409 stale_claim_epoch` and an ended Round `409 round_not_open`. Reconcile never changes a Round's state, its Ticket's Status, the slot or the lock; a repeat changes nothing.
- These cases stay distinct and are never collapsed into one another:
  - **Lost contact**: heartbeats stopped. It proves nothing about execution.
  - **Unknown execution**: the runner cannot say whether the Round's execution is alive.
  - **Stale report**: a report carries an epoch that is not the Round's current one, or comes from another runner. Galley rejects it with no change.
  - **Confirmed cessation**: the runner's own evidence that execution stopped, reported as `stop_confirmed` or `interrupted`.
- Only confirmed cessation or the Owner's attestation ("Stranded Round") ends an open Round as Stopped or Interrupted. Nothing closes or unlocks a Round because a check failed, and reconciliation never starts duplicate execution.
- Michelin retries a report for at most 5 minutes, then reconciles. Authority checks and acknowledgements retry without that bound.

## Swiftlet → Galley owner-command boundary

Swiftlet submits owner commands to Galley; it never talks to Michelin, never mutates Ticket/Round records directly, and never reads the database directly. Representative owner commands used across the lifecycle: create a Ticket, set it Ready (`POST /api/tickets/{id}/status`), assign an Agent (`PUT /api/tickets/{id}/assignee`), reorder the queue (`POST /api/tickets/{id}/position`), request rework (`POST /api/tickets/{id}/rework`), accept a Ticket (`POST /api/tickets/{id}/accept`), archive a Ticket, read a Ticket's Rounds (`GET /api/tickets/{id}/rounds`) and a Round's activity (`GET /api/tickets/{id}/rounds/{roundId}/activity?before=`), request Stop (`POST /api/tickets/{id}/stop`), answer a question, approve or decline a Permission request, revoke a grant (`POST /api/grants/{grantId}/revoke`), add Round Feedback to a delivered Round (`POST /api/tickets/{id}/rounds/{roundId}/feedback`), and attest a stranded Round's cessation. Rework is available only to an Agent-assigned Ticket in In Review with no open Round and the inputs Ready requires. Each becomes a Galley-authoritative record; where the command affects an open Round, Galley exposes the resulting instruction to Michelin through the pulled-commands mechanism above. Swiftlet only ever renders what Galley returns.

## What this contract does not decide

- Payload shapes are not restated here; see [`contracts/openapi.yaml`](../../contracts/openapi.yaml).
- No queue technology is chosen; see [ADR 0003](../adr/0003-postgresql-work-claims-before-queue.md).
- Human-review/merge evidence is **D2**. Exceptional PR transitions are **D4**. Grill Mode scheduling relative to the single active-Round slot is **D6**. None of these are resolved here. Agent/Template assignment and human workflow follow the separately accepted [D3 decision](../decisions/d3-agent-template-compatibility.md).
